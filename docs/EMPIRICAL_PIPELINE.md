# Raw-source paired execution pipeline

Current outcome: [formal disposition, November 23](../reports/formal_decision_20261123/README.md).
The original study remains inconclusive; deployment is rejected. No new cohort is enrolled.

## Source and availability boundary

`research/roadmap/empirical_pipeline.py` validates completed spool manifests and
segment hashes with the original verifier. It decodes the recorded public wire
messages, binds the original Binance/OKX instrument response bodies to their
digests, requires matching specifications and monotonic-time bracketing snapshots,
and converts OKX contracts into BTC using `ctVal * ctMult`. Current metadata cannot
qualify old tapes. Local hashes do not independently authenticate venue observations
or establish that a clock is UTC-accurate.

The information boundary is the **recorded single-writer start**, after callback
receipt and enqueue. Quote association is backward only, with a 500 ms maximum
age, connection/sequence checks and full raw-segment/line/byte-offset trace. Original
callback timestamps are retained. Raw records are never sorted to appear causal.
This convention includes queue delay in information availability; the modeled
50 ms decision delay begins afterwards. It is conservative application timing,
not exchange wire arrival, colocation latency or a repair of the frozen model.

This boundary requires a new source-bound prospective enrollment. It does not
silently change the frozen v1 observation clock or the registered primary study.

## Shared decisions and accounting

Every observed-window 10-second grid point is retained. Both policies need valid
features on both venues, with a 100 ms lookback. Scores are L/2 and L/2+B/2,
using the existing 12 bps threshold. Ineligible features remain explicit.

Independent counterfactual orders request 0.001 BTC at the recorded follower BBO
50 ms later and exit 1000 ms after entry. Insufficient entry depth produces an
explicit rejection. Unknown or insufficient exits retain known entry fees and
residual inventory, with unknown net value. Both modeled fills incur 5 bps fees;
bid/ask spread is already embedded. Cash-flow conservation is checked with decimal
arithmetic. The two policies are alternatives, not simultaneous consumers of depth.

This is a displayed-book opportunity model. It does not measure fill races,
impact, funding, margin, liquidation or actual trading-account profitability.

## Failed capture handling and inference

Default loading rejects incomplete or faulted capture evidence. The explicit
`--faulted-activity-only` mode retains faults, feature traces and action counts,
but computes **zero execution outcomes**. The November 23 long and short attempts
both stopped with Binance transport errors. An independent restart retained all
prior bytes. Neither failure is replaced or promoted into a qualified observation.

Even a clean local rehearsal is unenrolled. The CLI forces confirmatory intervals
to unavailable and never authorizes deployment. The paired-inference module remains
independently tested, but a complete registered-calendar assembler, authenticated
enrollment, independent clock evidence, fully bound controls/sensitivities and
future untouched dates are still needed. No command-line boolean grants those.

```sh
uv run --frozen python -m research.roadmap.timestamp_audit \
  --path /path/to/original.jsonl --out /tmp/new-order-audit.json

uv run --frozen python -m research.roadmap.empirical_pipeline \
  --spool /path/to/spool --metadata-dir /path/to/bracketing-snapshots \
  --out /tmp/new-paired-rehearsal

# Only for diagnosing sealed partial captures, never for return inference:
uv run --frozen python -m research.roadmap.empirical_pipeline \
  --spool /path/to/faulted-spool --metadata-dir /path/to/bracketing-snapshots \
  --faulted-activity-only --out /tmp/new-outcome-free-activity
```

Snapshot names are `binance-before.json`, `binance-after.json`, `okx-before.json`
and `okx-after.json`, generated by `research.roadmap.public_instruments` on the
same monotonic clock around capture. Outputs include the complete paired ledger,
summary, source trace and checksum inventory. Existing output directories are rejected.

## Preservation

The approved destination remains GitHub Releases. The cloud connection can create
API objects but upload-host authentication failed. `archive_transfer.py` stages
only the approved public rehearsal archive and checksums as bounded, unreferenced
Git blobs; they never enter commit history. A manually dispatched repository worker
verifies the supplied manifest SHA256, each part, every archive member and existing
asset identity before uploading without replacement. It downloads the assets again
and compares bytes. This is readback/integrity evidence, not Object Lock or WORM
retention; administrators can modify Release assets. Private account exports,
credentials and private logs are excluded from this public transfer flow.

## Meaningful checks

`tests/test_formal_pipeline.py` exercises actual spool loading, original-response
metadata binding, raw offsets, overtaking in the unchanged original recorder,
both-side cash/fee accounting, depth rejection, reconnects, unknown exits, missing
grid points and blocked inference. `tests/test_public_archive_transfer.py` tests
blob identity, malicious archive paths, corrupted members and refusal to overwrite
a conflicting remote asset. Synthetic tests establish mechanics, not market edge.
